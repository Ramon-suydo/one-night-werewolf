# Staged delivery

Each stage ends with lint, typecheck, tests and a local commit. The final gate adds a production build, multiplayer browser/security captures, bundle budgets and mobile audits.

1. Audit/removals: one all-3D runtime; private microphone-free communication; three-width phase/control inventory.
2. Headless rules: deterministic Classic/Solo engine, Doppelgänger, legal deck sets, fixed queue and table-driven tests.
3. Network/security: private secrets storage, public projection, authenticated own-view endpoint, idempotent commands, schemas and traffic audit.
4. Director: server deadlines, reveal/dawn/readiness/vote locks, disconnect defaults and automatic next deal.
5. World-first HUD: four-zone controls, one drawer, concise instructions and contextual world selection.
6. Interaction: raycast tablets, hold-to-peek/lock, local trails, avatar reactions and claims.
7. Cinematics/audio: skippable camera rails, original procedural sound, phase lighting, low-cost particles and calm variants.
8. Original art/world: twelve rune tablets, atlas, world landmarks, exploration and private discoveries.
9. Replay: sanitized result-only timeline, ghost swaps/peeks, filters and static calm diagrams.
10. Final polish: adaptive all-3D tiers, F3 metrics, production/mobile audits, free-tier simulation, complete deployment instructions.

Completion is tracked by the corresponding Git checkpoints, not by aspirational feature flags. RULES_DECISIONS.md records the owner-verifiable ambiguities instead of silently changing the inventory or win conditions.
